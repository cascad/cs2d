# ⚔ CS2D

**Top-down PvP-подземелье на Rust + Bevy: одна комната на 16 человек, все против всех.**

Играть можно прямо в браузере, без установки: **[cs2d.unspec.tech](https://cs2d.unspec.tech)** — придумал ник, нажал «ИГРАТЬ», дерёшься. Нативные сборки (Windows / Linux / macOS) лежат в [релизах](https://github.com/cascad/cs2d/releases).

## Что сейчас в игре

- **Одна арена до 16 игроков**, PvP без команд: зашёл — дерись.
- **Ближний бой:** удар с замахом, **щит** (держишь — гасит и урон, и стан, но жрёт стамину), **перекат**, **баш-стан** (прерывает замах противника).
- **Гранаты:** отскакивают от стен, взрываются по таймеру или об стену, урон по области с затуханием — своей же банкой можно подорваться.
- **Неписи-монстры** для разогрева между стычками — счёт по ним в табло отдельный.
- **Туман войны и миникарта** — противника ещё надо найти.
- HP-бары над головами, всплывающий урон, трупы остаются лежать.
- **Табло (Tab):** счёт всех, кто онлайн + памятка управления.
- **Аккаунты по нику:** пароль опционален (закрепляет имя), счёт живёт на сервере и переживает реконнект.
- АФК-кик: минута без ввода — место освобождается.
- Звуки боя и эмбиент подземелья.

## Управление

| Клавиша | Действие |
| --- | --- |
| W / A / S / D | движение |
| ЛКМ | атака |
| ПКМ (держать) | блок |
| Пробел | перекат |
| Q | стан |
| G (держать, отпустить) | граната |
| Tab | табло и памятка |

## Как запустить локально

Нужен только стабильный Rust.

```bash
git clone https://github.com/cascad/cs2d.git
cd cs2d

# 1) сервер — при первом старте создаст server_config.toml рядом с собой
cargo run --release --bin server

# 2) нативный клиент — в соседнем терминале (можно несколько)
cargo run --release --bin client
```

Браузерный клиент (wasm) — через [Trunk](https://trunkrs.dev), сервер должен уже работать:

```bash
rustup target add wasm32-unknown-unknown
cargo install trunk

cd client && trunk serve      # → http://127.0.0.1:8080
```

Первая wasm-сборка небыстрая (всегда release — debug-wasm не вытягивает тикрейт). Отладка: `RUST_LOG=debug cargo run --bin server`. Выкладка на свой VPS — `deploy/` (docker-compose + Caddy) и `WEB_CLIENT.md`.

## Как это работает

Один Rust-workspace: и сервер, и оба клиента (нативный и браузерный) собираются из общего кода на [Bevy 0.18](https://bevyengine.org/). Сервер — headless Bevy без рендера, гоняет всю симуляцию с фиксированным тиком ~66.7 Гц; клиент — это в первую очередь рендер, звук и отправка ввода.

## Сетевой код

Сервер авторитетен во всём: движение, удары, блоки, гранаты и неписи считаются только на нём, клиенты шлют голый ввод. Поверх транспорта — [lightyear](https://github.com/cBournhonesque/lightyear) 0.26: своего персонажа клиент **предсказывает** локально (ввод отзывается мгновенно, при расхождении с сервером — откат и перепроигрывание), остальных **интерполирует** между подтверждёнными состояниями. Транспорта два: нативный клиент ходит по UDP (`:6000`, там же TCP-мета для списка серверов), браузер — по WebTransport/QUIC (`:6001`) с self-signed сертификатом, digest которого страница получает у сервера.

Пинг перемеривается постоянно, и задержка ввода пересчитывается по живой оценке — кривой первый замер (например, джанк страницы при загрузке) не залипает на всю сессию. На это есть автотесты с эмуляцией нестабильной сети (`server/tests/unstable_ping.rs`). Два крейта lightyear точечно пропатчены в `vendor/` (размер пакета под MTU WebTransport и репликация при двух листенерах) — детали в корневом `Cargo.toml`.

## Структура

```
protocol/   # общие типы: сообщения, константы, геометрия, физика гранаты
netproto/   # сетевой слой поверх lightyear: симуляция боя, ввод, аккаунты
server/     # headless-сервер (+ интеграционные тесты сети)
client/     # клиент: натив и wasm из одного кода, index.html — лендинг
vendor/     # точечные патчи lightyear_transport / lightyear_replication
deploy/     # docker-compose, Caddy, скрипт выкладки dist на VPS
assets/     # спрайты, шрифты, звуки
```

## Особенности

- **Один код — три бинаря:** headless-сервер, нативный клиент, wasm-клиент.
- **Браузер — полноценный клиент**, не просмотрщик: тот же предикт, тот же тикрейт, что и в нативе.
- Релизы нативных сборок собираются CI автоматически по тегу `v*`.
- Игровой журнал изменений — в [CHANGELOG.md](CHANGELOG.md): что поменялось, почему и как.
